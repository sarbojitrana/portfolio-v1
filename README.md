# portfolio-v1

My portfolio, built as a hardware datasheet. Static HTML, generated by Go, with a projects
shelf that maintains itself.

**Live:** https://sarbojitrana.github.io/portfolio-v1/

## What's interesting about it

The projects section isn't hand-written. A scheduled job reads every public repository,
asks a model which ones are actually projects, writes the blurb from the README, and
screenshots any live deployment. Push a new repo with a README and it appears on the next
run; push notes or a solutions dump and it never does. The open-source ledger and both
competitive-programming panels come from the same job, straight out of the GitHub,
Codeforces and LeetCode APIs.

Section 02 is a working model of the middleware chain from
[nexus](https://github.com/sarbojitrana/nexus) — same order, same token bucket, same
cache-aside. Empty the bucket and the rate limiter answers 429 before the request reaches
the database.

## Layout

```
cmd/build      data/ + web/ -> dist/
cmd/refresh    GitHub + Codeforces + LeetCode + Claude -> data/
internal/
  ghapi        repos, merged pull requests, contribution calendar
  codeforces   profile, rating history, solved-by-rating buckets
  leetcode     GraphQL profile, contest history, acceptance rate
  describe     the classify-and-write-the-blurb call
  capture      headless screenshots, with blank-page rejection
  render       html/template + the JSON blob the page's script reads
  model        the shapes of everything under data/
web/           page.html.tmpl, style.css, app.js
data/          the generated JSON, plus overrides.json
assets/        avatar and captured previews
```

`cmd/build` writes two files. `dist/index.html` links `style.css`, `app.js` and `assets/`
for hosting. `dist/artifact.html` inlines all three, images included, as one self-contained
file.

## Running it

```bash
go run ./cmd/build                    # dist/ from whatever is in data/
go run ./cmd/refresh                  # refresh everything
go run ./cmd/refresh -only coding     # one dataset
go run ./cmd/refresh -shots=false -ai=false
```

`refresh` needs `ANTHROPIC_API_KEY` for the blurbs, a headless Chrome or Firefox on `PATH`
for the previews, and optionally `GITHUB_TOKEN` to lift the API rate limit. Both flags can
be turned off to refresh only the numbers.

## overrides.json

The model decides what a repository is; `data/overrides.json` decides everything it can't
know. Keys:

| key | effect |
| --- | --- |
| `always` | publish even if the classifier says no |
| `never` | never publish, no matter what |
| `wide` | render full width |
| `order` | shelf order; anything unlisted sorts to the end |
| `merge` | fold one repo into another (a frontend into its API) |
| `entries` | per-repo overrides: name, kind, blurb, facts, links, preview, terminal |

`entries[repo].terminal` is the recorded terminal output shown on CLI cards — the one
thing a screenshot can't capture. It also suppresses the preview for that card.

## Deploying

`deploy.yml` builds on every push to `main` and publishes `dist/` to GitHub Pages.
`refresh.yml` runs nightly, and opens a pull request when the data changes — nothing
reaches the site without a diff to look at. Add `ANTHROPIC_API_KEY` under repository
secrets before the first scheduled run.

## The résumé button

It points at `assets/resume.pdf` in
[sarbojitrana/sarbojitrana](https://github.com/sarbojitrana/sarbojitrana), served raw from
`main`. Replacing that file changes what everyone downloads, with no rebuild here.
